## 2.6 屏幕录制授权问题修复（第三轮）

**现象**：用户已在「系统设置 → 隐私与安全性 → 屏幕录制」中打开 PinShot 开关，但 PinShot 仍持续弹出权限引导（本轮真机确认）。

**原因**：开发期使用 ad-hoc 签名，每次 `make build` 后签名都会变化；系统里保留的是旧构建的授权条目，开关看起来是开的，但当前 App 的代码签名与条目不匹配。`CGPreflightScreenCaptureAccess()` 会一直返回 false。

**已做修复**：
1. 通过辅助功能检查确认了「PinShot 开关是打开的」但当前 App 未被识别；移除了失效的旧 TCC 条目，等待重新授权到当前构建。
2. 权限判断改为**先真实截一张图**再决定是否弹引导，避免预检缓存滞后造成误报。
3. 权限引导新增「重新检查」：用真实捕获探测，授权生效后可直接继续截图，无需重启。
4. 引导新增「授权无效？查看重新授权步骤」：说明如何用 − 删除旧条目、再通过 + 重新添加当前 `PinShot.app`，并可直接在 Finder 中显示 App；同时在用户从系统设置切回时自动重新探测。
5. 设置页「重新检查」也改为真实探测；失败时提示删除旧条目重新添加。

**用户侧一次性操作**：在引导里点「打开系统设置」→ 按系统提示授权/勾选 → 回到 PinShot 点「重新检查」；若系统设置里已有失效条目，按上面步骤删除并重新添加。之后不要再重新构建，授权即可保持。

## 2.9 屏幕录制授权问题与剪贴板兜底（第六轮）

**关键发现**：在「系统设置 → 屏幕录制」中删除 / 添加 App 需要 **Touch ID 或密码验证**；此前自动化删除时弹出了 Privacy & Security 验证框，未通过验证时删除/添加不会真正生效。用户侧需要在验证框中选择「Use Password…」或 Touch ID 后再操作。

**已做的修复**：
1. **稳定签名**：`build.sh` 改为 `codesign --requirements '=designated => identifier "com.kuxin.pinshot"'`，签名 requirement 从 cdhash 变为固定 identifier，跨构建稳定，重新构建不会让屏幕录制授权失效。
2. 权限引导的「重新授权步骤」补充：修改屏幕录制列表需要 Touch ID / 密码验证。
3. 新增 **「从剪贴板贴图…」** 菜单：系统截图 `⇧⌃⌘4` 复制到剪贴板 → PinShot 菜单 → 标注编辑器 → 贴图 / 复制 / 保存；不依赖屏幕录制权限。
4. 真机验证剪贴板链路：合成图片写入剪贴板 → 编辑器打开 → Enter → 生成贴图（1052×713 窗口），标注能力完整。

**当前状态**：屏幕录制列表里仍有旧的 PinShot 条目（开关为开但绑定旧构建）。需要用户在验证框通过 Touch ID/密码后：删除所有 PinShot 旧条目 → `+` 重新添加当前 `build/PinShot.app` → 勾选 → 重启 PinShot。由于已使用稳定 requirement，这次授权后后续构建应可持续保留。

## 2.10 TCC 陈旧条目最终修复（第七轮）

**根因确认**：系统「屏幕录制」里存在旧构建留下的 cdhash 授权条目（开关显示 ON，但当前 App 的签名 requirement 不匹配）。macOS 26 的授权提示没有 Allow 按钮，用户无法通过常规点按完成重新授权，形成「开关是开的、但一直未授权」的死循环。

**修复动作**：
- 在具备完整权限的环境执行 `tccutil reset ScreenCapture com.kuxin.pinshot`，清除陈旧条目；
- 重新启动 PinShot 后，⇧⌘2 捕获成功（覆盖层正常出现），说明授权已对新签名生效；
- 再次退出/重开 PinShot，⇧⌘2 仍然正常 → 权限已持久化；
- 真机验证完整链路：真实截图 → 标注编辑器 → Enter → 生成 600×450 贴图；
- 新增 `scripts/reset-screen-permission.sh` 供以后一键修复 TCC 陈旧条目；
- 构建脚本已使用稳定的 identifier-pinned designated requirement（`designated => identifier "com.kuxin.pinshot"`），后续重新构建理论上不再需要重新授权。

> 普通用户在「系统设置」里删除/添加条目时仍需 Touch ID / 密码验证；本修复不改变这一点。

## 3. 待人工验收（真实使用场景）

1. **首次授权**：在 `~/Applications` 双击启动 → 按 `⇧⌘2` → 系统弹「屏幕录制」→ 勾选 PinShot → 退出重开 → 再截图应正常（无黑屏）。
2. **真实热键**：全局 `⇧⌘2` / `⇧⌘1` 在任意前台 App 下触发、且不与常用应用冲突。
3. **多显示器**：在副屏框选，贴图出现在副屏正确位置（负坐标 / 不同缩放比例）。
4. **全屏应用**：在 Safari/视频全屏时，贴图仍可浮在上层（`fullScreenAuxiliary`）。
5. **保存**：工具栏「保存」→ NSSavePanel 默认桌面、默认文件名 `PinShot-yyyyMMdd-HHmmss.png`；右键「存储到桌面」自动去重。
6. **点击穿透**：贴图淡出后点击其位置应操作下层应用；鼠标扫回贴图应恢复。
7. **开机启动**：设置里打开 → 确认 `~/Library/LaunchAgents/com.kuxin.pinshot.login.plist` 指向当前 App；注销/重启验证；关闭后 plist 被删除。
8. **快捷键录制**：设置里改键、冲突提示、ESC 取消、改完立即生效（菜单/提示文案同步）。
9. **权限撤销**：系统设置里取消勾选 → 再截图应弹权限引导，而不是崩溃/黑屏。

## 4. 已知限制（来自实现）

- 一次拖拽只能在一个屏幕内框选，不支持跨屏框选。
- 贴图宽度 < 约 120pt 时悬浮工具栏放不下（改用右键菜单/键盘）。
- 滚轮事件落在贴图上不会转发给下层应用（纯 AppKit 无法安全转发）。
- 保存面板会短暂把前台切到 PinShot（accessory App 打开 NSSavePanel 的系统行为）。
- 贴图不跨启动持久化。
- 首次授权后必须重启 App 才能截图（macOS TCC 机制）；重新构建后 ad-hoc 签名变化可能导致需要重新授权。
